## 🔑 Key Concepts Explained

### **1. MongoDB Basics**

**NoSQL Database:**
- Stores data as JSON-like documents (not rigid tables)
- Collections = Tables (contain multiple documents)
- Documents = Rows (contain fields)
- Schema-less by default (but Mongoose adds schemas)

**Example MongoDB Document:**
```json
{
  "_id": "6a7d75e00f39f775b5c74a26",
  "title": "Learn MongoDB",
  "description": "Study NoSQL databases",
  "completed": false,
  "createdAt": "2026-08-13T07:44:32.317Z"
}
```

**Key Differences from SQL:**
| Feature | SQL | MongoDB |
|---------|-----|---------|
| Tables | Fixed structure | Collections (flexible) |
| Rows | Rigid format | Documents (JSON-like) |
| ID | Manual or auto-increment | Auto-generated ObjectId |
| Join | JOIN queries | Embedded documents |

---

### **2. Mongoose ODM (Object Document Mapper)**

**What is Mongoose?**
- Layer between your Node.js app and MongoDB
- Makes database operations easier and safer
- Adds schema validation
- Provides convenient methods (.find(), .create(), etc.)

**Schema vs Model:**
```javascript
// Schema = Blueprint (defines structure)
const taskSchema = new mongoose.Schema({
  title: { type: String, required: true },
  completed: { type: Boolean, default: false }
});

// Model = Interface (for database operations)
const Task = mongoose.model('Task', taskSchema);
```

### **4. MongoDB IDs vs Our Previous Counter**

**Before (In-Memory):**
```javascript
let taskIdCounter = 1;
const newTask = { id: taskIdCounter++, ... }; // Manual ID: 1, 2, 3...
```

**After (MongoDB):**
```javascript
const newTask = await Task.create({ ... });
// MongoDB auto-generates: _id: ObjectId("6a7d75e00f39f775b5c74a26")
```

**ObjectId Details:**
- 12-byte unique identifier
- Generated by MongoDB automatically
- Includes timestamp (first 4 bytes)
- Guarantees global uniqueness

### **5. CRUD Operations Conversion**

#### **GET (Read) - Task.find()**
```javascript
// Before: Array search
const tasks = tasks;

// After: MongoDB query
const tasks = await Task.find();
// Returns: All documents from "tasks" collection
```

#### **POST (Create) - Task.create()**
```javascript
// Before: Manual object creation
const newTask = { id: ++counter, title, description, ... };
tasks.push(newTask);

// After: Mongoose validation + MongoDB storage
const newTask = await Task.create({ title, description });
// - Validates against schema (title required!)
// - Saves to MongoDB
// - Returns document with auto-generated _id
```

#### **PUT (Update) - Task.findByIdAndUpdate()**
```javascript
// Before: Manual array search and update
const task = tasks.find(t => t.id === id);
task.title = newTitle;

// After: Database update with validation
const task = await Task.findByIdAndUpdate(
  id,
  { title: newTitle },
  { new: true, runValidators: true }
);
// - new: true → returns updated document
// - runValidators: true → validate after update
// - If not found → returns null (we check and return 404)
```

#### **DELETE (Remove) - Task.findByIdAndDelete()**
```javascript
// Before: Array splice
const index = tasks.findIndex(t => t.id === id);
tasks.splice(index, 1);

// After: Database deletion
const deletedTask = await Task.findByIdAndDelete(id);
// - Returns deleted document
// - Returns null if ID not found (404)
```

### **6. Error Handling with Mongoose**

**Three main error types:**

**1. ValidationError** (Schema validation fails)
```javascript
// Client sends: { description: "no title" }
// Schema requires: title (required: true)
// Error: ValidationError with field errors
// Response: 400 Bad Request

// Our handler converts to:
{
  "error": "Validation Error",
  "message": "Invalid fields: title",
  "status": 400
}
```

**2. CastError** (Invalid ID format)
```javascript
// If you use invalid MongoDB ID format
// Mongoose can't convert string to ObjectId
// Response: 400 Bad Request

{
  "error": "Invalid ID Format",
  "message": "The provided ID is not a valid MongoDB ID",
  "status": 400
}
```

**3. Generic Server Error**
```javascript
// Any other error
// Response: 500 Internal Server Error

{
  "error": "Internal Server Error",
  "message": "An unexpected error occurred. Please try again later.",
  "status": 500
}
```

**Key: Never expose error stack to client!**
```javascript
// ❌ DON'T send this to client:
res.json(err.stack); // Exposes internal info

// ✅ DO send clean message:
res.json({ error: 'Server Error', message: '...' });
```

### **7. Try/Catch Pattern for Async Database Operations**

**Why we use try/catch:**
- Database operations are async (take time)
- Errors can happen (network, validation, etc.)
- try/catch catches those errors
- Pass to error handler with `next(err)`

```javascript
// Pattern used in all routes:
app.get('/tasks', async (req, res, next) => {
  try {
    // Database operation
    const tasks = await Task.find();
    res.status(200).json(tasks);
  } catch (error) {
    // Pass error to global error handler
    next(error); // ← This triggers error middleware
  }
});
```

**Why pass to error handler?**
- Consistent error handling
- One place to format all errors
- Easy to log and debug

### **8. Mongoose Schema Features**

**Our Task Schema:**
```javascript
const taskSchema = new mongoose.Schema({
  // String, required (validation enforced)
  title: {
    type: String,
    required: true
  },

  // String, optional (can be undefined)
  description: {
    type: String
  },

  // Boolean with default value
  completed: {
    type: Boolean,
    default: false // New tasks = false automatically
  },

  // Auto-timestamp (set when created)
  createdAt: {
    type: Date,
    default: Date.now // ← Current time
  }
});
```

**Key Features:**
- **type**: Specifies data type (String, Number, Boolean, Date)
- **required: true**: Field must be provided (validation)
- **default**: Auto-set value if not provided
- **Date.now**: Special function that returns current timestamp

## 🚀 How the Pipeline Works

**Order matters! This is the exact sequence:**

```
1. Load Environment Variables
   ↓ (require('dotenv').config())

2. Import Dependencies
   ↓ (express, mongoose, Task model)

3. Express Setup
   ↓ (app.use(express.json()), CORS, static files)

4. MongoDB Connection
   ↓ (mongoose.connect with .env URI)

5. Logging Middleware
   ↓ (logs every request)

6. CRUD Routes
   ↓ (use async/await with try/catch)

7. Global Error Handler
   ↓ (catches all errors, formats response)

8. Start Server
   ↓ (app.listen(3000))
```

## 🔗 Connection Details

**What happens when server starts:**
1. Read `MONGO_URI` from `.env`
2. Call `mongoose.connect(MONGO_URI)`
3. Mongoose connects to MongoDB at localhost:27017
4. Database: "task-manager"
5. Collection: "tasks" (auto-created on first insert)

**Connection String Anatomy:**
```
mongodb://localhost:27017/task-manager
  └─ Protocol  └─ Host:Port  └─ Database Name
```
