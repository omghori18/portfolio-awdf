🔄 CRUD OPERATIONS - BEFORE vs AFTER

  BEFORE (In-Memory):
  ┌─────────────────────────────────────────┐
  │ let tasks = [];                         │
  │ let taskIdCounter = 1;                  │
  │                                         │
  │ POST: tasks.push({id: ++counter, ...}) │
  │ GET:  const task = tasks.find(...)     │
  │ PUT:  task.field = newValue            │
  │ DELETE: tasks.splice(index, 1)         │
  └─────────────────────────────────────────┘
  ❌ Data lost on restart
  ❌ Manual ID management
  ❌ No validation

  AFTER (MongoDB + Mongoose):
  ┌────────────────────────────────────────┐
  │ POST:   await Task.create({...})       │
  │ GET:    await Task.find()              │
  │ PUT:    await Task.findByIdAndUpdate() │
  │ DELETE: await Task.findByIdAndDelete() │
  └────────────────────────────────────────┘
  ✅ Data persists forever
  ✅ MongoDB generates IDs
  ✅ Schema validation enforced

📚 CONCEPTS MASTERED

  MongoDB:
  ├─ NoSQL database (document-based)
  ├─ Collections (like tables)
  ├─ Documents (JSON objects)
  ├─ ObjectId (auto-generated unique ID)
  └─ Persistent storage

  Mongoose:
  ├─ ODM (Object Document Mapper)
  ├─ Schema definition & validation
  ├─ Model methods (.find, .create, etc.)
  ├─ Error handling (ValidationError, CastError)
  └─ Type conversion & defaults

  Best Practices:
  ├─ Environment variables for secrets
  ├─ Try/catch for async operations
  ├─ Global error handler
  ├─ Clean error responses (no stack traces)
  ├─ Schema validation at database level
  ├─ Proper HTTP status codes
  └─ Data persistence checking
